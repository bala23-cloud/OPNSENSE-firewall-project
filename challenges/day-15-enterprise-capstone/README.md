# Day 15 — Enterprise Firewall Capstone

**Guide status:** Documentation complete. Capstone execution and final validation have not yet been recorded.

## Scenario
A small company needs a documented firewall deployment that protects internal systems while allowing approved business traffic.

## Objective
Bring the lab topics together into a design that can be explained, tested and maintained.

## Lab activities
- Draw the final topology and identify trust zones, interfaces and gateways.
- Review firewall rules and confirm that each has a clear purpose.
- Review aliases, NAT, port forwarding, DHCP and DNS settings used in the lab.
- Summarize monitoring, log investigation and any IDS/IPS or VPN work actually performed.
- Document backup, recovery, change control and rollback considerations.
- List features that remain outside the current lab's capabilities.

## Validation approach
Run a final test matrix covering approved and denied traffic. Correlate test results with firewall logs and states. Review the configuration for overly broad access and confirm that the documented topology matches the real lab.

## Key lesson
A professional firewall project is more than a configuration screenshot. It needs a clear design, justified policies, repeatable tests, honest results and known limitations.

## Final report contents
Include the architecture, security objectives, implemented configuration, test cases, observed results, troubleshooting notes, limitations and future improvements. Use only evidence collected from the actual lab.
